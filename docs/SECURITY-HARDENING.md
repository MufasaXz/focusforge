# FocusForge implementation and security handover — 2026-11-14

This covers the Flutter/Android app, Pip Worker, optional historical Firebase Functions and the separate `focusforge-web` repository. Source changes and local tests do not establish production deployment or legal compliance in 177 countries. The baseline source audit, resolved dependency inventories, read-only platform findings and redacted scans are retained in `/home/aosp/project/security-audit-2026-11-14/`. No user accounts or production content were modified during this work.

Pip is now fully on-device. The app no longer sends coaching requests or
creates cloud feedback/consent records, and has no cloud-consent popup or
online toggle. Account export and deletion still cover historical Pip server
records, including consent and feedback. The Worker and historical Functions
remain separate server code; their controls below are historical audit findings,
not an online answer path in the current app.

## Implemented

- Pip answers entirely with local rules and bundled lessons. Old consent keys are ignored; no choice is required to use Pip. Optional account/social services remain separate.
- Pip's local rules now give study-total/remaining-goal coaching, subject-need priorities, exact time-budget/Pomodoro plans including breaks, recall/spacing techniques, mock-test error review, exam-date nudges and useful unknown-question guidance. Existing plans, charts, reminders and timer actions remain. This is an improved deterministic local engine, **not machine-learning training**. The engine has no network dependency; independently enabled account/social services may still use the internet.
- Historical online clients and the server used redaction of common identifying patterns; old clients also redacted known profile identifiers. The current Pip client sends no coaching requests. For the retained server API, only six bounded numeric study context fields can reach a provider. Free-form subject/exam/app labels and UsageStats are excluded. Redaction reduces identifying data, not guarantees anonymity.
- Retained Worker schemas reject unknown/malformed fields, questions over 300 characters, unrecognised history roles, more than eight turns, oversized turn/report text and invalid totals. Bodies are streamed with a 16 KiB cap. Auth/revocation checks, UTC daily quotas, per-account/address/global burst limits, origin allowlisting and no-store/security headers protect requests. Obvious instruction/secret extraction attempts are refused before a model call. Model calls have no tools or server credentials in their prompts; arbitrary prompt injection is not claimed solved by a regex.
- The historical server integration with Gemini has explicit low-threshold safety settings and child-appropriate instructions. A safety refusal is never retried on Groq. Provider/key details, raw responses and stack traces are not rendered as public errors. TLS requests do not follow redirects carrying tokens/keys.
- The retained server report endpoint routes reports through the website's authenticated account-data API into fenced Firestore transactions. A report cannot race the immutable deletion fence and create new retained data afterward. Reports expire after 90 days; the signed minute scheduler sweeps expired reports and short-lived counters. Old chronological KV reports remain accessible through paged, owner-filtered Worker export/erasure. A read-only production key listing found **zero** legacy KV reports on the audit date.
- App JSON export now combines account-filtered local records, app-owned Android preferences, Firebase account metadata/private records/own sharing rows, and historical Pip reports/consent records. The web account page also offers **Export My Data (JSON)** for cloud records. Password hashes, bearer/refresh tokens and another user's private cache are excluded. Failure of any page prevents a false completed export.
- App and web deletion erase auxiliary records/reports, recursively remove the user's private Firestore descendants (including missing-parent/unknown descendants), retire legacy pairing/guardian links, remove group memberships/own sharing rows, and delete Firebase Auth last. A cloud failure retains credentials for retry. Android then resets live state, stops blocking, cancels reminders, clears native preferences/interception queues and temporary cache. Website deletion cannot remotely wipe phone-local records, provider logs, gallery originals or files the user exported elsewhere.
- Release Gradle and a release-only manifest explicitly disable debugging; cleartext and backups remain disabled. R8 minification/resource shrinking stay enabled, with narrowly scoped ProGuard metadata rules. `bash tool/build_secure_release.sh` adds Dart obfuscation and writes private symbol files outside the repository. It copies the newly generated AGP bundle explicitly, avoiding Flutter's display-name selection of old bundles already in the output directory.
- Website account sessions/Firestore cache remain in memory. Account operations forward App Check when available. The site has an updated CSP for the Worker data route, HSTS and popup-compatible opener isolation. The existing branded Firebase reset-email templates are preserved.
