# FocusForge implementation and security handover — 2026-11-14

This covers the Flutter/Android app, Pip Worker, optional historical Firebase Functions and the separate `focusforge-web` repository. Source changes and local tests do not establish production deployment or legal compliance in 177 countries. The baseline source audit, resolved dependency inventories, read-only platform findings and redacted scans are retained in `/home/aosp/project/security-audit-2026-11-14/`. No user accounts or production content were modified during this work.

## Implemented

- First chat opening asks **Enable Cloud Study Coach?**, with equal outlined **Disagree (Offline Mode)** and **Agree & Enable** buttons. Either explicit choice persists as `ff.pip_cloud_consent` in the existing SharedPreferences namespace. Existing legacy choices are migrated, and account switching isolates the active choice. Dismissing grants nothing. Settings offers a one-tap **Pip Cloud Study Coach** switch; withdrawal stops future sends and discards in-flight results. A request already sent cannot be recalled.
- The requested body was adjusted to disclose recent messages and imperfect redaction. An absolute promise that personal identity stays on the device would be false for linked Firebase accounts and arbitrary free text. There is no adult-verification screen, new sign-up requirement or model jargon in the consent dialog.
- Pip's local rules now give study-total/remaining-goal coaching, subject-need priorities, exact time-budget/Pomodoro plans including breaks, recall/spacing techniques, mock-test error review, exam-date nudges and useful unknown-question guidance. Existing plans, charts, reminders and timer actions remain. This is an improved deterministic local engine, **not machine-learning training**. The engine has no network dependency; independently enabled account/social services may still use the internet.
- Client and server redact common identifying patterns; the client also redacts known profile identifiers. Only six bounded numeric study context fields can reach a provider. Free-form subject/exam/app labels and UsageStats are excluded. Redaction reduces identifying data, not guarantees anonymity.
- Worker schemas reject unknown/malformed fields, questions over 300 characters, unrecognised history roles, more than eight turns, oversized turn/report text and invalid totals. Bodies are streamed with a 16 KiB cap. Auth/revocation checks, UTC daily quotas, per-account/address/global burst limits, origin allowlisting and no-store/security headers protect requests. Obvious instruction/secret extraction attempts are refused before a model call. Model calls have no tools or server credentials in their prompts; arbitrary prompt injection is not claimed solved by a regex.
- Gemini has explicit low-threshold safety settings and child-appropriate instructions. A safety refusal is never retried on Groq. Provider/key details, raw responses and stack traces are not rendered as public errors. TLS requests do not follow redirects carrying tokens/keys.
- New reports go through the website's authenticated account-data API into fenced Firestore transactions. A report cannot race the immutable deletion fence and create new retained data afterward. Reports expire after 90 days; the signed minute scheduler sweeps expired reports and short-lived counters. Old chronological KV reports remain accessible through paged, owner-filtered Worker export/erasure. A read-only production key listing found **zero** legacy KV reports on the audit date.
- App JSON export now combines account-filtered local records, app-owned Android preferences, Firebase account metadata/private records/own sharing rows, and current/historical Pip reports. The web account page also offers **Export My Data (JSON)** for cloud records. Password hashes, bearer/refresh tokens and another user's private cache are excluded. Failure of any page prevents a false completed export.
- App and web deletion erase auxiliary records/reports, recursively remove the user's private Firestore descendants (including missing-parent/unknown descendants), retire legacy pairing/guardian links, remove group memberships/own sharing rows, and delete Firebase Auth last. A cloud failure retains credentials for retry. Android then resets live state, stops blocking, cancels reminders, clears native preferences/interception queues and temporary cache. Website deletion cannot remotely wipe phone-local records, provider logs, gallery originals or files the user exported elsewhere.
- Release Gradle and a release-only manifest explicitly disable debugging; cleartext and backups remain disabled. R8 minification/resource shrinking stay enabled, with narrowly scoped ProGuard metadata rules. `bash tool/build_secure_release.sh` adds Dart obfuscation and writes private symbol files outside the repository. It copies the newly generated AGP bundle explicitly, avoiding Flutter's display-name selection of old bundles already in the output directory.
- Website account sessions/Firestore cache remain in memory. Account operations forward App Check when available. The site has an updated CSP for the Worker data route, HSTS and popup-compatible opener isolation. The existing branded Firebase reset-email templates are preserved.

## Validation

- Full Flutter suite: **737 passing tests**; final targeted consent/accessibility, export, withdrawal and privacy tests also pass, including **23 account-control tests** after adding a device-cleanup-failure regression. Analyzer: **no issues**.
- Worker: **45 passing tests**, including malformed/oversized payloads, JWT failures, safety refusals, quota failure, instruction extraction, redaction and owner-filtered legacy report pages.
- Website: **33 passing tests** and production TypeScript/Vite/prerender build. Browser scripts pass at 320/390/768/1024/1440 widths, light/dark preferences, reduced motion and without JavaScript.
- Firestore/API emulator: **13 passing server tests**, including ownership-filtered exports, report/deletion races, recursive missing-parent/legacy cleanup and retained other-user data; **6 passing web deletion tests**; **37 passing Firestore rule tests**; **10 passing historical Functions tests**.
- Android `:app:testDebugUnitTest`: successful. Obfuscated release bundle: successfully built with R8. Merged release manifest explicitly has debugging/cleartext/backup **false**. Packaged Dart libraries for all three ABIs contain **no DWARF debug sections**; compiler warnings concern intermediate symbol generation, which AGP strips from installed libraries. Retain private symbol maps for crash symbolication.
- Refreshed reachable/reflog Git text scan plus current files: all current reachable/reflog text blobs and current unignored files, with counts recorded in `implementation-secret-scan.json`; no production-secret candidates requiring review and no historical `.jks`/keystore/key-properties paths. Known Firebase client configuration and fake test fixtures were distinguished from server secrets. Pattern scans cannot prove absence of every unknown or compressed credential format.
- No live-user deletion test, physical-device packet capture or broad production AI safety evaluation was performed. Existing release version remains `1.0.1+3001`; choose a higher version code before uploading another Play update. The new source is not deployed by a local build or Git commit.
