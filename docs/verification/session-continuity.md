# Session continuity across app updates

Startup previously marked every retained Firebase credential as awaiting recovery and temporarily hydrated its local profile as anonymous. That displayed the recovery modal after an update and could show the profile's account-link prompt despite a retained credential.

A verified, nonanonymous Firebase credential now resumes a matching, nonanonymous local profile immediately. Bootstrap keeps that confirmed session linked. Private-backup reconciliation runs in the background; cloud writes remain deferred until the server snapshot has been read and merged. This includes older linked profiles that predate private-backup markers. Offline failures retain the active local session and retry reconciliation.

Missing credentials, unverified/deleted credentials, mismatched profiles and explicit logout/login retain the existing account recovery and identity checks. No account is unlocked from a local profile alone. Signing out cancels deferred reconciliation without waiting for its network read and caches pending local data. Connected sessions still attempt their final upload.
